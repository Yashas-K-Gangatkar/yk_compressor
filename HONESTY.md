# What each benchmark actually measures — READ BEFORE CITING

- **real_index.rs / real_200_benchmark.rs** — exact-match lookup demos.
  The query IS the stored embedding (circular by construction). The
  "sequential scan" baseline is a Vec linear scan, NOT transformer
  attention. Supports claims about dict-vs-scan speed only.
- **faiss_1m_test.py / benchmark_vit.py** — self-retrieval protocol.
  FAISS "accuracy" numbers (7.2% / 35.1% / 91.9%) are artifacts of a
  top-1-self test on a corpus containing duplicate embeddings (ties +
  membership-vs-argmax check asymmetry). NOT evidence FAISS is slow or
  inaccurate at similarity search. The YK coordinate in faiss_1m_test.py
  uses the row index as Z — the temporal axis is not exercised.
- **real_billion.rs** — measures binary search over synthetic keys.
  Query keys are generated by the same formula as stored keys (found by
  construction). FAISS cost is a projected formula, not measured.
- **million_benchmark.rs / scale_benchmark.rs** — synthetic 4-byte tokens.
  "Sequential Attention" label is wrong; it is a filtered linear scan.
  The O(N^2) figure is an extrapolation, not an attention measurement.
- **pq_billion.py** — PQ implementation is a 1D projection per 96-dim
  subspace (8 of 768 dims retained). Its 8.87% reconstruction is a
  property of that shortcut, not of product quantization.
- **stair_benchmark.rs** — the only script here that measures similarity
  retrieval: perturbed queries vs brute-force ground truth (recall@10).

Nothing in this repo replaces or outperforms transformer attention; the
systems here are retrieval indexes that require the query key or vector
in advance. Attention computes over tokens whose identity is unknown.
